Inflow's frontend is built for responsiveness and real-time feel, leveraging the full capabilities of the Next.js App Router.

## Framework & Routing

- **Next.js App Router**: We use nested layouts and loading states to provide a smooth user experience.
- **Client vs Server Components**:
  - **Server Components**: Used for data fetching in the dashboard and rendering static documentation.
  - **Client Components**: Used for interactive elements like charts (`Recharts`), forms (`React Hook Form`), and modals (`Radix UI`).

## State Management

- **SWR**: We use [SWR](https://swr.vercel.app/) for client-side data fetching. This allows for:
  - Automatic revalidation on focus.
  - Easy filtering of dashboard data without page reloads.
  - Cached analytics data for faster navigation.
- **React State**: Used sparingly for local UI states (e.g., toggling a sidebar or a modal).

## UI & Component Library

- **Design System**: Built on top of **Radix UI** primitives and customized with **Vanilla CSS**.
- **Theming**: Integrated with `next-themes` to support Light and Dark modes seamlessly.
- **Charts**: We use **Recharts** for all analytics visualizations. Components are wrapped in a `ClientOnly` wrapper to avoid hydration mismatches.

## Dashboard Patterns

1. **Website Selection**: The organization ID is stored in the user session, and the active website is typically managed via the URL path (e.g., `/dashboard/website/[id]`).
2. **Filtering**: The `RangeSelector` component updates URL search parameters, which are then used by both Server Components (initial load) and `SWR` (subsequent updates) to fetch filtered data.

## Deployment

The frontend is optimized for deployment on Vercel or as a standalone Node.js application via Docker.
