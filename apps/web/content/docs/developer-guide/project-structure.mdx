Inflow follows a standard Next.js App Router structure with additional layers for services and database management.

## Root Directory

```text
.
├── content/             # Documentation content (MDX)
├── public/              # Static assets (images, fonts, analytics.js)
├── src/
│   ├── app/             # Next.js App Router (Routes & APIs)
│   ├── components/      # Reusable React components
│   ├── configs/         # Global configuration files
│   ├── db/              # Drizzle schema and client
│   ├── hooks/           # Custom React hooks
│   ├── lib/             # Utility functions and shared logic
│   ├── migrations/      # SQL migrations generated by Drizzle
│   ├── server/          # Server-side services and actions
│   └── styles/          # Global CSS and themes
├── tests/               # Unit and integration tests
├── biome.json           # Linting and formatting rules
├── docker-compose.yml   # Local dev services (DB, Redis)
├── drizzle.config.ts    # Drizzle ORM configuration
└── package.json         # Dependencies and scripts
```

## Key Directories Explained

### `src/app`
Contains all the pages and API routes.
- `(app)`: Protected dashboard routes.
- `(auth)`: Login, signup, and password reset routes.
- `api/track`: The ingestion endpoint (Edge runtime).
- `api/website/[id]/analytics`: Data fetching for the dashboard.

### `src/components`
Organized by scope:
- `site/`: Public-facing components (Hero, Footer).
- `dashboard/`: Analytics charts and tables.
- `ui/`: Base components (Buttons, Inputs) from Shadcn/UI patterns.

### `src/server`
Contains the business logic decoupled from the routes:
- `services/`: Complex logic like `AnalyticsService` or `TeamService`.
- `actions/`: Next.js Server Actions for form submissions.

### `src/db`
- `schema.ts`: The single source of truth for the database structure.
- `drizzle.ts`: Database client initialization.

### `public/analytics.js`
The client-side tracking script. This is served statically and included in the user's website.
