This page explains how we build and maintain Inflow day-to-day.

## Git Branching Strategy

- **`main`**: The production-ready branch. All merges here should be stable.
- **`develop`**: The integration branch for new features.
- **Feature Branches**: Named `feature/[name]`. Created from `develop` and merged back via Pull Request.
- **Hotfix Branches**: Named `hotfix/[name]`. Created from `main` to address critical production issues.

## Typical Development Cycle

1. **Pull the latest changes**: `git checkout develop && git pull`.
2. **Create a branch**: `git checkout -b feature/my-new-feature`.
3. **Run local services**: `docker compose up -d`.
4. **Start Dev Server**: `bun run dev`.
5. **Implement changes**: Follow the [Coding Standards](/docs/developer-guide/coding-standards).
6. **Self-Review**: Run `bun run lint` and `bun run test` locally.
7. **Submit PR**: Push your branch and open a Pull Request to `develop`.

## Build Process

We use Next.js's built-in build system.

- **Type Checking**: Performed during `bun run build`.
- **Linting**: We use **Biome** for fast linting and formatting.
- **Minification**: Handled automatically by Next.js/Turbopack.

## Pre-deployment Checklist

Before merging a PR, ensure:
- [ ] No linting or formatting errors.
- [ ] All existing tests pass.
- [ ] New tests added for major logic changes.
- [ ] Documentation updated if features or APIs changed.
