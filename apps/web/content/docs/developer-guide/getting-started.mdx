Follow these steps to get a local instance of Inflow running.

## Prerequisites

Ensure you have the following installed:

- **Bun** (Standardized runtime and package manager for this workspace)
- **Docker** (For local PostgreSQL and Redis)
- **Git**

## Installation

Clone the repository and install dependencies:

```bash
git clone https://github.com/ibrahimraimi/inflow.git
cd inflow
bun install
```

## Environment Variables

Copy the example environment file:

```bash
cp .env.example .env
```

Fill in the required variables in `.env`. Key variables include:

- `DATABASE_URL`: Connection string for your PostgreSQL database.
- `BETTER_AUTH_SECRET`: A secure random string for authentication.
- `RESEND_API_KEY`: For sending verification and invitation emails.
- `UPSTASH_REDIS_REST_URL` & `TOKEN`: For rate limiting.

## Database Setup

We use Docker to run a local PostgreSQL database.

### 1. Start Docker Services
```bash
docker compose up -d
```

### 2. Push Schema
Use Drizzle to create the tables in your local database:
```bash
make db-push
```

## Running the Development Workspace

Start the development servers using Turborepo:

```bash
bun run dev
```

The applications will be available at:
- Dashboard: `http://localhost:3000`
- API: `http://localhost:3001`

## Available Workspace Scripts

Run these from the root directory:

- `bun run dev`: Starts all applications in development mode.
- `bun run build`: Creates a production build for the entire workspace.
- `bun run lint`: Runs Biome across all apps and packages.
- `bun run format`: Automatically formats the entire codebase.
- `make db-generate`: Generates Drizzle migrations for the core database.
- `make db-migrate`: Applies migrations to the database.
- `make ci`: Runs all CI checks (linting, type checking, building) locally.
