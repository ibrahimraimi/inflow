Consistency is key to a maintainable codebase. Please follow these guidelines:

## Code Quality Tools

We use [Biome](https://biomejs.dev/) for linting and formatting. It is significantly faster than ESLint/Prettier and provides unified rules.

- **Check Code**: `bun run lint`
- **Fix Formatting**: `bun run format`

## Naming Conventions

- **Files & Folders**: Use kebab-case (e.g., `user-service.ts`, `auth-modal.tsx`).
- **Components**: PascalCase (e.g., `<AnalyticsChart />`).
- **Variables & Functions**: camelCase (e.g., `const pageViews = 0;`).
- **Constants**: UPPER_SNAKE_CASE (e.g., `const MAX_RETRY_ATTEMPTS = 3;`).

## Folder Organization

- Place logic in `src/server` or `src/lib`.
- Place UI elements in `src/components`.
- Keep API routes minimal; delegate heavy lifting to service layers.

## Type Safety

- **TypeScript**: Avoid `any` at all costs. Use proper interfaces and types.
- **Zod**: Use Zod for all external data validation (API requests, environment variables).

## Best Practices

- **Functional Programming**: Favor immutability and pure functions where possible.
- **Component Composition**: Prefer composition over large, complex prop drillings.
- **Comments**: Write "why" comments, not "what" comments. Let the code explain the "what".
- **Errors**: Use descriptive error messages and handle potential failures gracefully (e.g., DB timeouts).
